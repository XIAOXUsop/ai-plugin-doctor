# 服务导入与路径选择指南

适用于发行任务验收的 `init` 导入流程。配置诊断继续使用 `scan`，无需先导入。

## 1. 先查看候选

```powershell
node dist/src/cli.js init "D:\项目\.mcp.json" --list
```

列出名称、是否支持和不支持原因，不启动服务、不创建文件，不展示参数值或环境变量值。支持服务根键 `mcpServers`、`servers`、`mcp_servers`；可读取 JSON、显式 `.jsonc`、VS Code 的 `.vscode/mcp.json` 和 TOML。JSONC 支持注释、尾逗号和 BOM。语法错误、重复键、非对象根键和超限文件停止导入。

传入目录时查找 `.mcp.json`、`mcp.json`、`mcp.jsonc`、`claude_desktop_config.json`、`.vscode/mcp.json`、`.cursor/mcp.json`、`config.toml`。找到多份时要求指定某个文件，不自动选择优先级；没有配置才查看 `package.json`。导入是读取所选文件，不替代客户端的加载来源诊断。

## 2. 明确选择服务和工作目录

```powershell
node dist/src/cli.js init "D:\项目\.mcp.json" "D:\验收\doctor.yaml" --server tools --cwd "D:\项目"
```

多个服务必须使用 `--server`；单个服务可省略。远程 HTTP、已禁用服务、客户端变量、envFile、认证或宿主控制字段不能直接迁移，会显示原因，避免静默丢弃配置后运行。仅支持明确的本地 stdio 子集；没有 `args` 时按空数组导入。对原客户端权限、信任和已有会话的判断仍需配置诊断或原生取证。

工作目录规则：

- 有 `--cwd`：使用该目录；相对值相对当前调用命令的目录。
- 没有 `--cwd`，源服务有 `cwd`：相对源配置文件所在目录解释。
- 两者都没有：默认源配置文件所在目录，并提示核对。它未必等于原客户端的默认启动目录；例如 VS Code 的配置在 `.vscode` 下时，通常需要明确指定实际工作区。
- 生成配置写入绝对 `cwd`。以后把生成配置移到另一个目录，不改变该目录；迁移到另一台机器仍需重新核对路径。

相对执行文件（如 `../bin/server.exe`）按工作目录转为绝对路径；裸命令（如 `node`）保留以使用 PATH。参数原样保留，既不把 `./literal-value` 猜成文件路径，也不改写包名或普通文本。进程从明确的工作目录启动，参数里的相对路径由目标程序解释。

导入成功会显示所选服务、来源、工作目录、参数数量和所需环境变量名。它不代表服务已连接。

## 3. 环境变量

已有 `${SHARED_TOKEN}` 引用原样保留。例如源服务的 `API_KEY` 指向 `${SHARED_TOKEN}`，所需变量仍为 `SHARED_TOKEN`，不会错误改为 `API_KEY`。

内联字符串值改成同名 `${VARIABLE}` 引用，不复制该值；使用前须在当前进程环境提供变量。`${env:...}`、`${input:...}`、默认值或拼接表达式不能自动迁移，先转换成此工具支持的明确值/引用。变量名必须合法，变量值必须为字符串。

## 4. 插件有多个本地入口

```powershell
node dist/src/cli.js init "D:\插件\package.json" --list
node dist/src/cli.js init "D:\插件\package.json" "D:\验收\doctor.yaml" --entry service
```

多个 `bin` 必须使用 `--entry` 选择名称；单个可省略。字符串 `bin` 的候选名是 `bin`，仅有 `main` 的候选名是 `main`。所选文件须已构建并存在；以 Node 启动该本地入口，不执行安装或包脚本。`--entry` 不能用于 MCP 服务文件，`--server` 不能用于 package 入口。

## 5. 导入后的操作

生成文件保留 `edit-me` 用例和空工具许可名单。先填写合适的测试任务及许可工具，再执行 `preflight` 或 `run`；导入和候选查看本身不调用模型。未知/重复/缺值选项会停止，已有输出拒绝覆盖，源文件不修改。

服务摘要现在包含固定工作目录、声明的环境变量引用及可识别的本地文件内容，目录参数不会被当成文件读取；不包括实际环境凭据值。与旧版本报告比较时，摘要算法变化本身可能显示 `server_changed`，需同时查看版本、工具面和任务证据，不能仅据此断言服务升级。
