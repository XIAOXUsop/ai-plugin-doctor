## 双 CLI 实测解释

第一组是命令不存在。两端静态均发现问题，Claude 原生连接 FAIL；Codex 的配置列表可以 PASS，因为该命令不启动服务，不能将 PASS 解释为连接正常。确认服务映射后，Claude 受限字段修复、Codex TOML 人工替换，分别重新扫描/原生核对/受控发现。

第二组是执行文件存在，但 args 指向不存在的服务脚本。两端受控检查 FAIL，Claude 原生连接 FAIL；按人工步骤核对脚本安装位置并只改合成 args，再分别取得 Codex cli-config、Claude native-service 和两端 controlled-replay 的 PASS。任意 args 重写不在自动修复范围。

全部主动实测使用隔离配置和已知空工具服务；没有调用业务工具或模型，没有修改或主动检查用户真实 MCP 定义。用户已经移除的访谈与试用反馈不计入本次门槛。

## 声明边界

Cursor/VS Code 是文件诊断、受限建议和人工原生取证，未声称已有 IDE 会话自动通过。HTTP/OAuth 完整主动诊断、远程宿主、信任/权限/认证自动修改按原计划延后。用户声明原生状态仍为 UNKNOWN；已有桌面会话与模型任务未通过本轮配置测试独立验证。

Windows Job Object 的关闭会终止所管理进程及普通后代；通过 WMI、系统服务等外部代理创建的程序不由本 Job 管理，不能称为隔离沙箱。[Microsoft 官方文档](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) 真实 Ctrl+C 验收在隐藏独立控制台使用官方信号 API，确实观测到 Node SIGINT 与后代退出。[控制台信号说明](https://learn.microsoft.com/en-us/windows/console/generateconsolectrlevent)

canary 零泄漏结论只覆盖验收注入与相应报告/终端路径。来源路径、服务/变量名称属于本地诊断证据，分享包进一步删除这些身份信息。备份可能包含秘密，仍保留本机并排除 Git；外部编辑器和云盘不遵守本工具锁，不能宣称跨文件绝对原子事务。
