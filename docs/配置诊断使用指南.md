# 跨客户端配置诊断使用指南

安装、构建与回归测试方法见 [README](../README.md)。

## 网络与已有会话排查

扫描区分模型侧和 MCP 侧的已知代理来源，记录协议类型、NO_PROXY 候选及证书路径是否存在，不保存代理凭据、证书内容或 NO_PROXY 原文。原生输出中的 401 只按明确线索分类为 model/mcp/unclassified，不推断第三方网关账号应与官方账号相同。

明确设置诊断进程的 HTTP(S) 回环代理后，可运行 `doctor network-check <scan.json> --client claude --out <new-file.json>`。它只建立 TCP 连接，不发送 HTTP、认证或模型请求；PASS 不代表 TLS、模型认证或原生客户端成功。用户给出的 33210 是端口上下文，不会被自动设置成系统代理。

VS Code 在相同工作区/Profile 使用 `MCP: List Servers` 查看选中服务和日志；仅有工具列表变更证据时执行 `MCP: Reset Cached Tools`。这些操作有官方支持，但本工具不自动重置缓存或信任。[官方配置参考](https://code.visualstudio.com/docs/agents/reference/mcp-configuration)

Cursor 在 Output 面板查看 MCP Logs，修改配置后重启原入口并重新核对工具。本机未验证 Cursor 原生会话，结果保留人工声明/unknown。[官方排查说明](https://prod.cursor.com/help/customization/mcp)

## 安装与开始

首版实测平台为 Windows x64、Node.js 24。构建使用系统自带 .NET Framework 4 编译器生成进程管理组件；缺少组件时主动检查会停止，不降级到无保护启动。无需 Python 或模型 API key。

```powershell
npm ci
npm run build
node dist/src/cli.js scan --workspace "D:\你的项目" --out runs/config-first
node dist/src/cli.js diagnose runs/config-first/scan.json
```

在新生成目录打开 `report.html`。所有输出路径要求不存在；每次检查保留独立证据。`scan` 仅读取已知配置路径及安装文件元数据，不运行版本命令、MCP 服务、辅助凭据命令、交互输入命令或模型。

明确原入口版本和类型时，可添加 `--versions codex=0.159.2,claude=2.1.89,vscode=1.120.0 --surfaces codex=codex-cli,claude=claude-cli,cursor=cursor-ide,vscode=vscode-chat`。版本来源标注为用户声明、安装包元数据或未观察；声明不会替代主动实测。版本超出规则验证范围时，相关推断降级为 unknown 并关闭相应自动修复。原生检查独立读取安装版本，陌生版本停止解析；桌面入口需在原入口取证。

高优先级或相关设置来源损坏、不可读时，可读字段保留为候选，不能据此判定原生已回退加载低层定义；修复先停止，处理来源缺口或取得原生证据后重新扫描。Codex `--profile` 记录选择并用于相同 Profile 的原生 CLI 核对，静态合并保持 unknown；不猜测或读取 `<profile>.config.toml` 文件，不基于这一猜测导出修复片段。

报告包含有效字段来源、被覆盖链、节点行列/偏移、未加载来源及跨客户端不同字段。args、env/header 值、URL 路径和查询隐藏；同一次扫描的凭据比较仅保存 equal/different/unknown，不保存凭据或 HMAC。

## 支持范围

| 入口 | 文件读取与解释 | 主动证据 | 修改 |
|---|---|---|---|
| Codex CLI 0.159.2 | 用户、明确 Profile、已知工作区项目来源；保留字段来源和信任缺口 | `mcp list --json` 确认本次 CLI 配置；stdio 回放独立报告 | TOML 人工修改，随后重新扫描 |
| Claude Code 2.1.89 | user/project/local；同名服务整项覆盖；已知禁用、审批和 deny 来源 | 指定服务的 `mcp get` 健康检查；stdio 回放 | 支持 JSON 的受限字段修改 |
| Cursor IDE | 全局/工作区 MCP 文件，官方优先级推断 | 原生日志人工取证；受支持 stdio 可单独回放 | JSON 受限字段；尚未实测 Cursor 原生会话 |
| VS Code 本地 Chat | 默认或明确 Profile MCP JSONC、工作区 MCP、对应 settings；input/discovery/access 标注观测缺口 | MCP: List Servers 人工取证；受支持 stdio 可单独回放 | JSONC 受限字段；尚未实测原生会话 |

系统/托管文件只读观察，不完整计算云端策略、MDM、注册表和托管提供的服务集合。文件存在或无法读取时相关服务状态为 unknown，修复转为人工动作。多根工作区、动态插件注册、远程 Agent Host、正在运行的桌面会话缓存不由本地文件扫描证明。

默认路径以本次诊断进程环境确定，可明确指定上下文：

```powershell
node dist/src/cli.js scan --workspace "D:\项目" --clients codex --codex-home "D:\Codex配置" --profile work --out runs/codex-work
node dist/src/cli.js scan --workspace "D:\项目" --clients claude --claude-config-dir "D:\Claude配置" --out runs/claude-work
node dist/src/cli.js scan --workspace "D:\项目" --clients vscode --vscode-config "C:\Users\你\AppData\Roaming\Code\User\profiles\指定配置\mcp.json" --out runs/vscode-profile
```

合成测试可用 `--home` 隔离用户目录。目标会话使用额外命令行覆盖时，追加 `--launch-overrides`，工具会标为未观测并保留原入口核对。远程窗口追加 `--location remote`；本地主动验证返回 UNSUPPORTED。

## 连接与原生检查

先在扫描输出中选择服务 ID，再主动检查。启动一个 MCP 服务本身可能产生副作用。

```powershell
node dist/src/cli.js check runs/config-first/scan.json --service 服务ID --out runs/replay.json
node dist/src/cli.js check runs/config-first/scan.json --service 服务ID --native --out runs/native.json
```

证据必须按类别阅读：

| evidenceKind | PASS 能说明什么 |
|---|---|
| file | 文件事实及规则推断，不能说明已有会话加载成功 |
| cli-config | 本次 Codex CLI 选中定义的 command/args/url/cwd 与扫描一致；不说明已连接 |
| controlled-replay | 诊断器环境中的 stdio 进程完成握手及工具发现；不说明原客户端成功 |
| native-service | 本次 Claude `mcp get` 显示服务已连接；不说明交互审批或模型实际调用 |
| native-session | 用户提交的原入口状态声明；未经独立验证，仍为 UNKNOWN |

Claude `mcp get` 会启动选中服务，且跳过交互信任提示；它还可能更新自身配置元数据。检查后若旧快照失效，重新扫描。诊断器拒绝使用已变化的旧配置继续修复。

stdio 回放只执行解析到的原生文件，不自动拼接 shell，不执行 `.cmd/.bat/.ps1` 包装，不加载 envFile、helper 或 input。基础环境限 PATH、用户目录和系统运行变量，再加定义明确传递的变量。握手/发现总时限 12 秒，输出上限 1 MiB，工具发现至多 8 页/1000 个。初始化、JSON-RPC 消息和工具列表使用当前固定 SDK 的 schema 校验；不完整结构、矛盾的 result/error 或协议错误不会得到 PASS。不会调用业务工具或模型，也不导出工具描述/schema/名称及原始进程输出。HTTP/OAuth 留给原生入口。

Windows 在目标程序开始执行前加入禁止 breakaway 的 Job Object，关闭 Job 时结束其进程；管理组件同时监视诊断进程存活。已验证超时、输出超限、取消、目标父进程先退出、诊断进程强制结束及真实 Ctrl+C 的收尾。连接/握手时限 6 秒、列工具 8 秒，另有总时限 12 秒和退出等待上限。Job Object 管理其直接拥有的程序和普通后代；经系统服务、WMI 等外部代理创建的程序不属于此保证，不把回放称为沙箱。[Windows 官方说明](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)

## 修复、复查和恢复

一次仅选择已核实的发现。不同客户端的同名服务只作为对比候选；工具不自动跨客户端同步，也不会因为差异就强制修改。

同名或入口字段相同的不同名服务存在歧义时，先用 `doctor map <scan.json> --services 服务ID1,服务ID2` 明确确认身份，再重新扫描。映射保存在工作区 `.doctor/service-map.json`，支持不同名称和多组映射；旧计划会因映射变化而失效。映射不证明不同账号、数据集或权限相同，已有映射的修改需人工审阅。

预览显示脱敏的旧字段、新语义值、目标作用域和影响范围。旧字符串值隐藏，变量引用可见，默认值隐藏；用户明确提供的新路径/类型会显示。TOML 命令或 cwd 修复导出可解析的人工片段，应替换指定字段，不能重复追加整张表；原始文件保持不动。

```powershell
node dist/src/cli.js plan runs/config-first/scan.json --finding 发现ID --value "C:\确认过的目录\node.exe" --out runs/plan.json
node dist/src/cli.js apply runs/plan.json --dry-run
node dist/src/cli.js apply runs/plan.json --out runs/operation.json
node dist/src/cli.js verify runs/operation.json --out runs/config-verified
node dist/src/cli.js restore runs/operation.json --out runs/recovery.json
```

明确变量方言和根键转换不需要 `--value`。执行路径/工作目录要求用户指定存在的绝对普通文件/目录；远程传输要求明确 `--value http`、`sse` 或 `ws`，不能仅凭 URL 猜测。

修复前核对全部扫描来源状态和内容哈希，重新验证修复动作与当前故障相符；按目标文件加独占锁，保留原始字节备份，分文件记录操作，再使用同目录临时文件替换。Windows 备份在创建时使用禁止继承、仅当前运行账户可访问的 ACL；替换保留目标文件的访问规则、所有者和继承保护状态。文件保护组件缺失时在写入前停止；无法建立权限时不继续修改。第二文件失败时尝试恢复本次已写入的文件。配置已被其他程序修改时拒绝覆盖。锁残留需人工核对相关进程与操作记录，再移除确认属于已结束操作的锁。

变量/路径修改保留其他 JSONC 文本；根键转换仅替换键名称，保留其余字节。测试覆盖注释、BOM、CRLF、无关字段与原始恢复。备份名为 `<配置路径>.doctor-backup-<操作ID>.bak`，可能包含原有秘密，默认留在本机且被 Git 忽略。

当前诊断进程最多同时运行 2 个受管检查，等待队列最多 16 个；排队取消不会启动服务。CLI 每次只选择一个服务。旧版本留下的备份未被此次自动改变权限，处理旧备份前应先核对其来源。

恢复也先验证备份哈希及当前文件版本。出现冲突不宣告全量恢复成功，可核对 recovery/operation 和备份后人工处理。独占锁防止本工具的并发修复；其他编辑器或 OneDrive 不遵守此锁，版本复核能检测常见冲突，但不提供与外部编辑器之间的原子比较交换事务。

`verify` 的 configuration PASS 只代表本次写入完整、未修改来源未变化、选中静态故障已消失。新扫描仍会列出其他问题，nativeSession 始终 UNKNOWN；请再用目标客户端复查。恢复后旧 operation 的 verify 会失败，这是预期状态。

## 原生人工取证

在 Cursor 的 MCP 服务列表/日志，或指定 VS Code Profile 的 `MCP: List Servers`，核对相同工作区、服务、时间与状态。自行填写：

```json
{
  "client": "vscode",
  "serverId": "来自扫描的服务ID",
  "workspace": "D:\\你的项目",
  "observedAt": "2026-10-02T12:00:00+08:00",
  "surface": "vscode-chat",
  "status": "connected"
}
```

```powershell
node dist/src/cli.js import-evidence runs/config-first/scan.json native-record.json --out runs/manual-evidence.json
```

入口允许 codex-cli/codex-desktop、claude-cli/claude-desktop-code、cursor-ide、vscode-chat，必须与客户端匹配。status 允许 connected/failed/unknown。原始日志、自由文本及额外字段丢弃，不把用户声明转换成自动 PASS。

## 本地与分享数据

本地 scan/HTML 保存来源路径、服务/变量名称及配置内容版本哈希；它们可能识别用户，应按本地诊断资料管理。args/env/headers 值、URL 凭据/路径/查询和自由文本配置不写入报告；报告 HTML 转义外部文本。凭据比较只在单次内存中使用临时 HMAC，报告仅记录 equal/different/unknown，表达式不当成真实凭据相等。

```powershell
node dist/src/cli.js share runs/config-first/scan.json --out runs/share.json
```

分享文件再次按类别白名单生成，仅保留客户端、规则、状态、数量及差异字段类别；剔除本地路径、名称、哈希和执行入口。没有自动上传。不要分享本机备份、操作记录或原始配置。

## 常见结果

| 发现 | 动作 |
|---|---|
| VAR_DIALECT_MISMATCH | Claude 使用 `${VAR}`，Cursor/VS Code 使用 `${env:VAR}`；预览明确引用的转换 |
| VAR_MISSING | 只说明诊断进程缺失变量，在真实客户端启动环境核对 |
| CFG_SHADOWED | 检查来源，覆盖可能有意；Claude 整项覆盖不继承低层 env |
| PROJECT_TRUST_REQUIRED | 在 Codex 原入口审阅信任，不自动修改信任 |
| MULTIPLE_INSTALLATIONS / WINDOWS_LAUNCHER_MISMATCH | 核对目标 PATH 与包装方式；终端成功不能直接证明 IDE 成功 |
| CONFIG_UNSAFE_PATH | 诊断器拒绝符号链接/重解析或非普通文件；这不证明目标客户端配置坏了 |
| FIELD_UNOBSERVED | 当前版本/入口没有充分依据，留给原生核对 |

旧 `init/preflight/run/report/compare` 是插件发行任务验收流程，有独立报告模型与费用说明；不要用隔离任务 PASS 替代本次原生配置验收。
