# 整体交付实施方案 · 2026-10-03

## 目标与执行约定

将已实施的配置诊断首版、发行任务验收与工程打磨作为一个完整交付版本：代码经复核、本地完整验收、可复现源码包、GitHub 同步、远端 Windows CI 成功，最终逐条交付核验。

用户要求先给大步骤方案，再持续严格执行直至完成。因此阶段之间不要求重复确认；发现失败先定位、修复、重新验证。有实际登录、权限或外部服务阻断时说明具体原因，并继续不依赖阻断的工作。不得把定义好的 CI、旧测试数量或本地通过代替当前远端/原生证据。

范围维持已有方案：Windows 本地、受限 stdio、Codex/Claude CLI；Cursor/VS Code 文件诊断及人工原生取证。HTTP/OAuth、远程/IDE 原生自动验收、信任/权限自动修改不扩入本轮。访谈和试用反馈已由用户移除。测试只使用隔离合成服务；不执行用户业务工具或扩大模型测试预算。

## G1：范围冻结、代码与交付复核

产出：当前源码与待提交文件清单、修复记录、清晰的文档入口。

验收条件：

- 检查扫描/修复/进程收尾/导入/报告/源码包的关键边界，修复可复现的交付缺口。
- 明确包内文件、发布源码和本机证据的边界；不提交认证、密钥、备份、服务映射、依赖目录或新运行数据。
- 不改写历史证据，不以历史文档的失败/过时数量冒充当前状态。
- CI 命令对失败能明确返回非零；无外部凭据也能运行合成验收。

## G2：当前版本完整本地验收

产出：工作目录 JUnit、独立交付目录 JUnit、源码/整包摘要、关键原生结果。

验收条件：

- 当前构建与全量测试 0 失败、0 跳过；数量以实际新增后的结果记录。
- 从最终源码 ZIP 标准解压，不复制 dist/node_modules；锁文件独立安装、构建、源文件校验、全量测试和 CLI/报告 smoke 全部成功。
- 同一份源码重复打包与解压后重打包字节一致。
- 用隔离服务重跑双 CLI 的受支持关键原生实验及 TOML 语义检查；实际版本不符时停止套用旧结论，修正证据或明确未通过。
- 对进入 GitHub 的修改确认无真实秘密；原生日志与原始配置仅保留本机。

## G3：提交整理与 GitHub 同步

既有目标：`https://github.com/XIAOXUsop/ai-plugin-doctor.git`。提交前再次核对远端和分支，普通快进推送；不强制覆盖，不重写历史，不删除用户本地配置。

验收条件：

- 新增/修改源码、必要脚本、CI 和项目文档明确纳入提交；历史本机配置可从 Git 跟踪移除但保留本地文件，并加忽略规则。
- 提交前复核 staged 文件，不使用包含本机研究/运行材料的无差别全目录提交。
- 推送后本地提交与远端 HEAD 一致；记录提交 SHA 和仓库链接。
- 若需要新凭据，由用户在可信登录界面完成，不要求发送令牌。

## G4：远端 Windows CI 实际验证

验收条件：

- 确认对应交付提交的 Actions run 已实际触发。
- 安装、构建、全量测试、源码打包、独立解压/重建/校验/测试和 smoke 全部成功。
- 失败时获取日志、复现并修复，提交后重新验证；只对同一交付提交的最终成功作通过结论。
- 记录 run URL、实际 head SHA、结束状态和源码包产物；发布产物不含本机配置或认证。

## G5：最终闭环核验

产出：最终验收表及可复核链接。

验收条件：G1–G4 全部有当前证据，远端 SHA/CI SHA 对应已交付源码，最终源码包和本地复现记录一致；未满足的必要门槛必须列为未完成，不宣称严格完成。

交付清单：源码包及摘要、安装/使用指南、GitHub 提交、成功 CI run、逐项验收记录。此完成结论仅覆盖上述明确范围，不宣称没有潜在缺陷。
